# 배포와 운영

## 초기 배포

- 단일 VPS
- Docker 기반 서비스 구성
- Go 서버
- 정적 WASM/웹 클라이언트
- 같은 호스트의 로컬 영구 볼륨을 사용하는 SQLite
- 리버스 프록시
- HTTPS/WSS

## 환경

- 로컬 개발은 HTTP/WS 허용 가능
- 운영은 HTTPS/WSS만 허용
- 비밀값은 이미지에 포함하지 않고 환경변수 또는 시크릿으로 주입

## 서버 로그

일반 서버 로그:

- 로그인 성공/실패
- 방 생성/삭제
- 게임 시작/종료
- 재접속
- CPU 대체
- 규칙 오류
- 프로토콜 오류
- 예외
- 응답 시간
- 활성 WebSocket 수
- 관리자 조치

게임 감사 로그:

- 모든 던지기 결과
- 큐 추가/제거
- 말 선택과 이동
- 업기·잡기
- CPU 선택
- 연결 상태
- 시간 초과
- 일시 정지
- 승패·무효 이유
- 채팅

## 장애 정책

- 서버 프로세스 재시작 시 진행 중 경기 무효
- 경기 무효 기록 저장
- 방 폐쇄
- 클라이언트에 종료 사유 전달
- 자동 경기 복구는 v1 범위 밖
- 경기 상태 변경 이벤트 저장 실패 시 자동 정지하고 타이머를 보존
- 최초 실패 뒤 최대 3회 저장 재시도
- 재시도 소진 시 경기 무효
- 채팅 저장 실패는 경기 진행과 채팅 전달을 차단하지 않음

SQLite WAL 파일은 DB 상태의 일부로 취급한다. 운영 백업은 SQLite 백업 API 또는 검증된 체크포인트 절차를 사용하고, 복원 시험을 정기적으로 수행한다.

## 모니터링 기본 지표

- 현재 접속자
- 활성 방
- 진행 경기
- WebSocket 연결 수
- 명령 처리 지연
- 오류율
- DB 쓰기 지연
- 재접속 횟수
- CPU 대체 횟수
- SQLite 쓰기 큐 길이와 대기 시간
- WAL 크기와 체크포인트 지연
- 경기 이벤트 저장 재시도 및 저장 장애 무효 경기 수
- 채팅 로그 저장 실패 수
