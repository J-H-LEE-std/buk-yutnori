# ADR-0002: 명령 멱등성과 경기 이벤트 확정

- 상태: 채택
- 결정일: 2026-07-23

## 맥락

WebSocket 재전송과 재접속은 같은 사용자 명령을 중복 전달할 수 있다. 경기 상태 변경 이벤트는 감사 로그에 남아야 하며, DB 저장 실패가 서버의 정본 상태와 로그를 갈라놓아서는 안 된다.

## 결정

- 멱등 키는 인증된 `(user_id, command_id)`다.
- 성공과 결정적 거부를 포함한 최초 처리 결과를 저장한다.
- 중복은 명령을 다시 실행하지 않고 최초 `COMMAND_RESULT`와 이벤트 sequence 범위를 재전송한다.
- 같은 키로 서로 다른 명령 내용이 오면 프로토콜 오류로 거부한다.
- 동시 중복은 하나의 처리만 실행하고 나머지는 그 결과를 공유한다.
- 경기 상태 변경 이벤트는 DB 저장 성공 뒤 메모리 상태, sequence 및 방송을 확정한다.
- 최초 저장 실패 시 운영 자동 정지 후 3회 재시도한다. 재시도 소진 시 경기를 무효 처리한다.
- 자동 정지 중 새 경기 상태 변경 명령은 저장 장애 오류로 거부하고 나중 실행을 위해 큐에 쌓지 않는다.
- DB 자체 장애로 무효 이벤트를 저장할 수 없는 경우에만 메모리 종료와 구조화된 비상 로그를 허용한다.
- 채팅 저장 실패는 경기 또는 채팅 전달을 중단하지 않는다.

## 결과

- 재전송이 상태를 두 번 변경하지 않는다.
- 클라이언트는 중복 요청에서도 최초 결과를 결정적으로 복구할 수 있다.
- DB 지연이 경기 진행 지연으로 직접 나타나므로 부하 시험과 지표가 필요하다.
- v1은 서버 재시작 후 경기 복구를 하지 않으므로, DB 저장 직후 프로세스가 종료되는 좁은 구간은 감사 로그만 남고 경기 자체는 무효가 될 수 있다.
