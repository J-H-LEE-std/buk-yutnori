# 남은 항목

## 구현 차단 항목

이번 명세 정합성 수정으로 전체 보드, 북 후보, 완주 거리, 백도 경로 상태의 알려진 구현 차단 항목은 해소되었다. 전체 보드 그래프는 `spec/board_graph.yaml`이 정본이며 추가 보드 자료를 기다리지 않는다.

최소 WebSocket 명령·이벤트와 재접속 스냅샷 스키마는 초안이 마련되었다. 시작 확인, 멱등 처리, 방 생명주기 단위 sequence, 일시 정지 및 저장 장애 정책은 확정되었다. 실제 네트워크 제품 구현 전에 아래 나머지 프로토콜 세부 정책을 결정해야 한다.

## 프로토콜 세부 정책 미결정

- `ERROR` 이벤트의 표준 오류 코드 목록
- WebSocket heartbeat/idle timeout과 graceful shutdown 시 active connection 종료 정책

## 방·운영 흐름 미결정

- 운영자 강제 종료 시 전적과 무효 사유

## 구현 전 ADR 필요

- 이벤트 저장 방식과 인덱스

경기 기록은 사람이 읽기 쉬운 기보 형태로 던지기와 그 결과로 선택한 이동을
`{윷 결과}{[말 ID][이동 전 위치][이동 후 위치]}`처럼 압축하는 방안을 검토한다.
다만 이 표기만으로는 결과 큐, 업기·잡기, CPU 선택, 연결 상태, 시간 초과, 일시 정지,
승패와 무효 사유까지 포함하는 감사 이벤트를 손실 없이 표현할 수 없다. 저장 ADR에서는
다음 선택지를 비교한다.

- 방 sequence별 typed event와 구조화된 payload를 정본으로 저장하고 기보는 여기서 파생
- 턴 또는 경기 단위의 압축 기보를 정본으로 저장
- typed event를 정본으로 유지하면서 종료 시 조회용 압축 기보를 함께 생성

비교 기준은 상태 확정 전 저장 계약, 멱등 재전송, 감사 가능성, 경기 기록 조회 비용,
스키마 버전 변경과 SQLite 인덱스 비용이다.

방 actor/goroutine 모델은 ADR-0012로 확정되었다.

## 제품 세부 정책 미결정

- 닉네임 최소/최대 길이
- 닉네임 허용 문자
- 닉네임 설정 전 사용자의 방·채팅 진입 및 표시 정책
- 방 제목 유무 및 길이
- 방 비밀번호 길이·시도 제한
- 채팅·게임 로그 보존 기간
- 사용자 계정 삭제 정책
- 브라우저 최소 지원 버전
- 관리자 역할과 인증 방식

## UI 조정 가능 항목

- `spec/board_graph.yaml`의 렌더링 좌표는 참고 그림에서 얻은 근사값이다.
- 화면 비율, 모바일 배치, 말 겹침 오프셋은 실제 클라이언트 구현 중 조정한다.
- 좌표 조정은 논리 그래프의 노드와 연결을 바꾸지 않는다.

## 비차단 권장값

- 닉네임 2~20 grapheme
- 방 제목 1~50 grapheme
- 방 비밀번호 최대 64자
- 프로토콜 JSON
- v1 DB SQLite. 단일 서버·로컬 디스크 전제가 깨지거나 부하 시험에서 전환 조건이 확인되면 PostgreSQL 재검토
