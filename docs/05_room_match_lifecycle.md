# 방과 경기 생명주기

## 서버 실행 소유권

- 살아 있는 방마다 application actor 하나가 해당 방의 authoritative command를
  직렬 실행한다.
- 서버 소유 타이머 만료와 같은 내부 상태 전이도 타이머 goroutine에서 방 상태를
  직접 변경하지 않고 같은 actor mailbox에 제출한다.
- actor가 수락한 명령은 transport 연결 취소와 분리하여 결과 확정까지 실행한다.
- actor가 수락한 내부 상태 전이도 제출자 취소와 분리하여 완료한다.
- 방 폐쇄는 대기 중인 제출을 포함해 새 command admission을 먼저 중단하고 actor가
  이미 수락한 현재 command 또는 내부 상태 전이를 완료한 뒤
  room-lifetime 멱등 결과와 sequence 경계를 정리한다.
- 서로 다른 방의 actor는 독립적으로 실행한다.

구체적인 admission, context와 cleanup 순서는
`docs/adr/0012_room_actor_execution_boundary.md`를 따른다.

## 방 생성

- 로그인 사용자만 생성
- 공개방
- 방 제목은 필수이며 Unicode extended grapheme cluster 기준 1~25자다. 한글 음절
  한 글자는 1자로 계산한다.
- 비밀번호는 선택 사항이다. 설정할 경우 전체 문자열이 정규식
  `^[0-9a-zA-Z]{4,16}$`와 일치해야 하며, 숫자와 영문 대·소문자만 허용한다.
- 비밀번호를 설정하지 않은 방은 입장 비밀번호를 요구하지 않는다.
- 최대 플레이어: 2/4/6/8
- 최대 인원은 시작 필수 인원이 아님
- 최소 시작 인원: 각 팀 1명, 총 2명
- 두 팀의 플레이어 수가 동일해야 시작 가능
- 플레이어+관전자 합계 최대 20명
- 방장은 게임 시작 전 대기실에서 A/B 팀에 CPU 플레이어를 추가하거나 제거할 수 있다.
  CPU 플레이어는 자동 준비·자동 시작 확인하며, 경기 중에는 서버 CPU 정책이 항상
  제어한다. 비방장, 시작 확인 중, 경기 중의 CPU 좌석 변경은 거부한다.
- CPU 플레이어는 사용자 계정·세션·profile·재접속·전적의 대상이 아니다. 시작 가능성의
  팀 인원·최대 플레이어 수에는 일반 플레이어와 동일하게 포함한다.
- 독립 CPU 플레이어는 별도 진영이나 규칙 객체가 아니다. 일반 플레이어와 같은 팀·턴
  순서·말을 가지며, 자신의 턴에는 시간 초과·연결 이탈 대체 CPU와 같은 서버 CPU 정책을
  사용한다.

## 팀과 준비

- 플레이어가 A/B 팀을 직접 선택
- 모든 플레이어가 준비 완료해야 시작 가능
- 새로 입장한 플레이어의 준비 상태는 `false`다.
- 플레이어는 방장이 경기 시작을 요청하기 전까지 자신의 준비 상태를 설정하거나
  해제할 수 있다.
- 준비 완료 플레이어는 자신의 팀을 변경할 수 없다. 먼저 준비를 해제해야 한다.
- 방장은 경기 시작 요청 전까지 상세 설정을 변경할 수 있다.
- 방 설정 변경, 미준비 플레이어의 팀 변경과 플레이어 입·퇴장은 기존 플레이어의
  준비 상태를 자동으로 해제하지 않는다.
- 방장이 시작을 요청한 시점에 서버가 최소 인원, 팀 균형과 전원 준비 상태를 다시
  검증한다.

## 게임 시작 확인

1. 방장이 시작 요청
2. 서버가 모든 플레이어에게 시작 확인 요청과 서버 기준 10초의 마감 시각을 전송
3. 제한 시간 안에 확인 응답을 보내지 않은 사용자는 방에서 제외
4. 한 명이라도 제외되면 시작을 취소
5. 남은 사용자는 대기실로 돌아감
6. 남은 플레이어 전원의 준비 상태를 `false`로 초기화
7. 팀 균형이 다시 맞아야 재시작 가능

- 확인 응답은 마감 시각 이전에 서버가 수신한 것만 유효하다.
- 마감 뒤 도착한 응답은 시작을 되살리지 않으며, 해당 시작 시도에 대한 만료 응답으로 처리한다.
- 시작 확인 중 플레이어가 연결을 잃으면 미응답으로 처리한다.
- 미응답자 퇴장, 시작 취소, 남은 플레이어 준비 상태 초기화는 하나의 방 상태 전이로 확정한다.

## 방장

### 게임 시작 전
방장이 나가면 접속자 중 무작위로 권한을 위임한다. 구현 시 플레이어 우선 위임을 기술 기본안으로 하며, 플레이어가 0명이면 방을 폐쇄한다.
`LEAVE_ROOM` 후에도 이 위임·폐쇄 규칙이 적용되며, ADR-0019 후속 구현의 나가기
command는 이를 별도 행동으로 바꾸지 않는다.

### 게임 중
- 게임 종료까지 방장 변경 없음
- 방장이 끊기면 CPU가 게임 행동 대체
- 방장의 유일한 게임 중 특별 권한은 경기당 1회 일시 정지

### 게임 종료
- 기존 방장이 연결 중이면 유지
- 연결되어 있지 않으면 접속 중인 플레이어만 후보로 무작위 위임
- 플레이어가 0명이면 관전자가 남아 있어도 즉시 방 폐쇄

## 강퇴

- 게임 시작 전 대기실에서만 방장이 플레이어 강퇴 가능
- 게임 중 강퇴 불가
- 운영자는 경기 강제 종료 가능
- `LEAVE_ROOM`·`KICK_PLAYER`·`REMOVE_CPU_PLAYER`의 대상 분리와 메뉴 계약은
  ADR-0019 후속 구현에서 적용한다. UI는 같은 멤버 메뉴를 사용해도 CPU를 사람
  강퇴 command로 처리하지 않는다.

## 경기 진행

- 시작 전 연결 끊김 발생 시 게임 시작 취소
- `in_match` 중 HTTP 입장은 새 관전자에게만 허용한다. 새 플레이어 입장과
  시작 확인 중의 모든 새 멤버십은 계속 거부한다.
- 경기 중 새 관전자 입장은 비밀번호·중복 멤버십·플레이어+관전자 합산 20명 제한을
  동일하게 적용하며, 팀·준비 상태·현재 경기 판정은 바꾸지 않는다.
- 시작 후 개인 이탈은 CPU 대체
- 한 팀 전원이 이탈해도 CPU로 계속 진행
- 양 팀의 모든 플레이어가 연결을 잃으면 30초 유예
- 30초 안에 한 명이라도 복귀하면 계속 진행
- 30초 동안 복귀자가 없으면 경기 무효 및 방 폐쇄
- 남은 관전자는 로비로 이동

## 경기 종료

- 정상 종료 후 같은 방 대기실로 복귀
- 기존 팀 유지, 대기실에서 자유롭게 변경 가능
- 기존 방 설정 유지, 방장이 변경 가능
- 재대결마다 팀 내 순서와 선공을 다시 추첨
- 마지막 사용자가 나가면 빈 방 즉시 삭제
- 게임 기록 저장과 방 삭제는 별개다. 기록은 경기 종료 시 저장한다.
