# 요구사항 권위와 상태

## 상태 구분

- **확정 요구사항**: 사용자가 직접 결정한 제품·게임 규칙
- **기술 기본안**: 구현을 진행하기 위한 권장 기본값. ADR로 변경 가능
- **미결정**: 자료 또는 제품 결정이 더 필요한 항목

## 확정 요구사항

- 웹 브라우저 기반 실시간 멀티플레이
- 서버와 클라이언트 분리
- Go 게임 서버
- raylib 기반 WebAssembly 클라이언트
- raylib/WASM 클라이언트 구현 언어 C
- 서버 권위형 판정
- Google 로그인 필수
- 공개방 생성, 비밀번호 가능
- 방 제목은 필수이며 Unicode extended grapheme cluster 기준 1~25자
- 방 비밀번호는 선택 사항이며, 설정할 경우 전체 문자열이 정규식
  `^[0-9a-zA-Z]{4,16}$`와 일치
- 두 팀 구조, 최대 8인
- 관전·채팅·재접속·CPU 대체
- 게임 규칙과 특수 규칙 전체
- 단일 VPS Docker 배포 희망
- v1 서버 재시작 복구 없음
- v1 데이터베이스는 단일 서버의 로컬 영구 볼륨에서 사용하는 SQLite
- 시작 확인 제한 시간 10초, 실패 시 미응답자 퇴장·시작 취소·남은 전원 준비 해제
- 명령 멱등 키 `(user_id, command_id)`와 중복 시 최초 처리 결과 재전송
- 경기 상태 변경 이벤트는 DB 저장 성공 뒤 서버 상태로 확정
- 저장 실패 시 자동 정지 후 1초, 2초, 5초 간격으로 재시도하고 최종 실패 시 경기 무효, 채팅 저장 실패는 경기 비차단
- 채팅은 부가 기능이며 새로고침·재접속 snapshot에서 이전 채팅 기록을 복구하지 않고 새 연결 뒤의 메시지만 표시
- 윷판은 참먹이를 출발점으로 하는 `spec/board_graph.yaml` 구조
- 전체 윷판의 노드와 논리 연결은 확정되었으며 `spec/board_graph.yaml`이 기계 판독 가능한 정본

## 기술 기본안

- HTTP + WebSocket 분리
- JSON v1 프로토콜
- HTTPS/WSS 운영
- Secure/HttpOnly/SameSite 30일 세션 쿠키
- 스냅샷 + 누락 이벤트 재동기화
- 명령별 `command_id`
- 서버 이벤트별 `sequence`
- 규칙 엔진을 순수 도메인 모듈로 분리

## 미결정 또는 추가 자료 필요

- 로그·채팅 보존 기간
- 닉네임의 길이/문자 제한
- 지원 브라우저의 정확한 최소 버전
- 관리자 UI의 상세 UX

기술 기본안은 구현자가 임의로 바꾸지 말고 ADR에 근거와 영향을 남긴다.
