# 배포와 운영

## 초기 배포

- 단일 VPS
- Docker 기반 서비스 구성
- Go 서버
- 정적 WASM/웹 클라이언트
- 같은 호스트의 로컬 영구 볼륨을 사용하는 SQLite
- 리버스 프록시
- HTTPS/WSS

## 환경

- 로컬 개발은 HTTP/WS 허용 가능
- 운영은 HTTPS/WSS만 허용
- 리버스 프록시는 WebSocket upgrade와 외부 Host·Origin을 보존한다. 서버는
  cross-host Origin과 Origin 없는 브라우저 연결을 거부한다.
- 비밀값은 이미지에 포함하지 않고 환경변수 또는 시크릿으로 주입
- `BUK_GOOGLE_CLIENT_ID`: Google OAuth web client ID. 공개 설정이지만 환경별
  audience를 고정하기 위해 서버 설정으로 주입
- `BUK_LISTEN_ADDR`: 프로토타입 서버 주소, 기본 `127.0.0.1:8080`
- `BUK_WEB_ROOT`: 생성된 WASM 정적 파일 경로, 기본 `build/client/web`

인증 계정과 세션은 SQLite에 영구 저장하므로 유효한 30일 쿠키는 서버 재시작 뒤에도
계속 인증된다. 다만 진행 중 방·경기 런타임은 v1에서 재시작 복구 대상이 아니며,
운영 배포의 Docker·HTTPS/WSS·모니터링·부하 시험 요구는 Milestone 6에서 별도로
충족한다.

WebSocket 수신 메시지는 16 KiB로 제한하고 압축은 기본 비활성이다. active connection
graceful shutdown과 heartbeat/idle timeout 정책은 connection registry 도입 전
확정해야 한다.

## 서버 로그

일반 서버 로그:

- 로그인 성공/실패
- 방 생성/삭제
- 게임 시작/종료
- 재접속
- CPU 대체
- 규칙 오류
- 프로토콜 오류
- 예외
- 응답 시간
- 활성 WebSocket 수
- 관리자 조치

게임 감사 로그:

- 모든 던지기 결과
- 큐 추가/제거
- 말 선택과 이동
- 업기·잡기
- CPU 선택
- 연결 상태
- 시간 초과
- 일시 정지
- 승패·무효 이유
- 채팅

## 장애 정책

- 서버 프로세스 재시작 시 진행 중 경기 무효
- 경기 무효 기록 저장
- 방 폐쇄
- 클라이언트에 종료 사유 전달
- 자동 경기 복구는 v1 범위 밖
- 경기 상태 변경 이벤트 저장 실패 시 자동 정지하고 타이머를 보존
- 최초 실패 뒤 1초, 2초, 5초 간격으로 최대 3회 저장 재시도
- 재시도 소진 시 경기 무효
- 채팅 저장 실패는 경기 진행과 채팅 전달을 차단하지 않음

SQLite WAL 파일은 DB 상태의 일부로 취급한다. 운영 백업은 SQLite 백업 API 또는 검증된 체크포인트 절차를 사용하고, 복원 시험을 정기적으로 수행한다.
