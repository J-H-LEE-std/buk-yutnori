# 턴과 결과 큐 상태 머신

## 핵심 개념

- 모든 던지기 결과는 안정적인 `token_id`, 결과 값, 생성 원인을 가진 `ResultToken`으로 생성된다.
- 생성 원인은 최초 던지기, 윷 추가 던지기, 모 추가 던지기, 잡기 추가 던지기를 구분한다.
- 결과 큐의 기본 순서는 FIFO다.
- `movement_order = fifo`이면 모든 토큰을 엄격한 FIFO로 처리한다.
- `movement_order = free`이면 첫 번째 북 토큰 전까지의 일반 이동 토큰 중에서 자유롭게 선택할 수 있다.
- 북은 순서 장벽이다. 북 뒤의 토큰은 북이 처리되기 전에 선택할 수 없다.

## 기본 턴

1. `TURN_START`
2. `WAIT_THROW`
3. 서버가 결과 생성
4. 결과를 큐에 추가
5. 윷/모 추가 던지기 조건이면 즉시 `WAIT_THROW` 반복
6. 던지기 연쇄 종료 후 `RESOLVE_QUEUE`
7. 결과 선택
8. 말/경로 선택
9. 이동 적용
10. 업기·잡기·완주 판정
11. 잡기 추가 던지기 조건이면 즉시 던지고 큐 뒤에 추가
12. 큐 처리 재개
13. 큐가 비면 `TURN_END`

## 채택된 후속 이동 선택 계약

이 절은 #149 후속 구현과 동시에 기존 v1의 결과 선택·말 선택 command를 대체한다.
그 구현 전의 실행 계약은 위 기본 턴과 현재 schema를 따른다.

- `movement_order=fifo`에서는 서버가 큐 선두 토큰의 합법적인 말 후보만 제공한다.
  사용자는 말을 직접 선택한다.
- `movement_order=free`에서는 서버가 합법적인 `(결과 토큰, 말, 경로)` 조합을
  제공한다. 사용자는 먼저 말을 고르고, 그 말에 적용 가능한 토큰이 둘 이상일 때만
  그중 하나를 고른다.
- 클라이언트는 후보·경로·완주 가능성을 계산하지 않는다. 서버가 제공하지 않은 말,
  토큰 또는 경로는 선택할 수 없다.
- 대기 장소 말은 서버 후보이면 선택 가능하다. 완주 말은 완료 표시로 남지만 어떤
  후보에도 포함하지 않는다.
- 선택이 끝나면 클라이언트는 `SELECT_MOVE(token_id, piece_id)` 하나를 보낸다.
  서버는 `RESULT_SELECTED`를 먼저, `PIECE_SELECTED`를 다음 sequence로 기록하되
  둘을 하나의 상태 전이와 저장 transaction으로 확정한다.

세부 protocol과 재접속 표현은 ADR-0019를 따른다.

## 북 처리

- 북이 선택 가능한 큐 선두가 되면 사용자 말 선택을 받지 않는다.
- 서버가 북 후보를 계산하고 가중 무작위 선택한다.
- 강제 이동과 후속 잡기·업기를 적용한다.
- 북 토큰을 제거한다.
- 후보가 없으면 북을 제거하고 턴을 즉시 종료한다.

## 제한 시간

### 던지기 시간
- 10초
- 20초(기본)
- 30초

### 이동 처리 시간
- 30초
- 60초
- 90초(기본)
- 120초
- 150초

이동 처리 시간에는 다음 선택이 모두 포함된다.

- 결과 선택
- 말 선택
- 지름길 선택
- 북 동률은 서버 선택이므로 사용자 시간에 포함하지 않음

추가 던지기가 발생하면:

1. 던지기 타이머를 방 설정값으로 초기화
2. 던지기 종료 후 이동 타이머를 방 설정값으로 초기화

## 시간 초과

- 현재 플레이어의 해당 턴 전체를 CPU가 이어서 완료한다.
- 플레이어 연결이 유지되어 있으면 다음 자기 차례부터 다시 직접 조작한다.
- CPU는 방 옵션과 관계없이 결과 큐를 FIFO로 처리한다.

## 재접속 중 제어권

- CPU가 아직 서버에 확정하지 않은 선택은 취소할 수 있다.
- 이미 확정된 윷 결과·이동·잡기 이벤트는 롤백하지 않는다.
- 재접속 플레이어는 다음 미확정 의사결정 지점부터 제어권을 회수한다.

## 일시 정지

- 경기당 1회
- 방장만 시작
- 1분 단위로 1~30분 중 선택
- 타이머와 CPU 모두 정지
- 정지 직전의 활성 턴 타이머 종류와 남은 밀리초를 그대로 보존
- 방장만 조기 재개
- 지정 시간 종료 시 자동 재개
- 방장이 연결을 잃으면 즉시 자동 재개
- 재개 시 보존한 남은 시간부터 같은 타이머를 계속 진행
- 정지 중에도 양 팀 전원 이탈 30초 감시는 계속 진행
- 정지 중 전원 이탈 유예가 만료되면 경기를 무효 처리하고 방을 폐쇄

DB 저장 장애로 인한 자동 정지는 사용자가 사용하는 경기당 1회 일시 정지와 별개인 운영 상태다. 이 상태에서도 활성 턴 타이머를 보존하고, 전원 이탈 30초 감시는 계속한다.
