# 채팅, 관전, 관리자

## 채팅

- 메인 로비와 게임 화면에서 같은 인증 전체 채팅을 표시한다. 실제 방 membership와
  별개인 `room_id=lobby` scope이며 방/경기 sequence를 공유하지 않는다.
- 관전자 참여 가능
- 팀 전용 채팅 없음
- 메시지는 Unicode code point 기준 최대 200자
- 같은 사용자의 승인 메시지는 sliding 1초 구간에 최대 3개
- 프로토콜상 유효한 `SEND_CHAT` 시도는 rate limit이나 동일 메시지 거부 여부와
  관계없이 사용자별 발송 기록에 포함한다. sliding 5초 구간의 16번째 시도부터
  1분 채팅 차단
- 같은 사용자가 마지막 승인 메시지와 byte-for-byte 동일한 텍스트를 5초 미만에
  다시 보내면 거부하며 정확히 5초 뒤에는 허용
- 비속어 필터 없음
- 개인 음소거·차단·신고 없음
- 승인 채팅은 `room_events`의 `room_id=lobby` 행으로 비동기 최선노력 저장한다.
  저장 실패나 로그 queue 포화는 구조화 로그로 관측하지만 전달이나 경기를 중단하지
  않으며, 채팅은 재접속 replay 대상이 아니다.
- 보존 기간은 미결정
- 채팅은 부가 기능이며 새로고침·재접속 때 이전 채팅 목록을 복구하지 않는다.
  새 연결은 연결 이후 확정된 메시지만 표시한다.

인증 WebSocket 연결은 `lobby` 전체 채팅에 자동 구독한다. `SEND_CHAT`은 이 scope만
허용하고, 기존 `prototype-room`과 임의 방 ID는 거부한다. 서버는 확정 시점에 저장된
profile 닉네임을 `CHAT_MESSAGE.sender_nickname`으로 넣어 표시한다. profile이 아직 없거나
조회가 실패하면 채팅을 막지 않고 안정적인 내부 `user_id`를 표시자로 사용한다. 전체 채팅은 새 연결 이후 확정된 이벤트만 표시하며
재접속 snapshot에는 포함하지 않는다. 상세 경계는 ADR-0018과 ADR-0010을 따른다.

## 관전

- 로그인 사용자만 가능
- 진행 중 공개방을 방 목록에서 선택
- 비밀방은 비밀번호 필요
- `in_match` 중 새 입장은 관전자만 가능하며, 시작 확인 중에는 새 입장을 허용하지
  않는다. 기존 비밀번호·중복 멤버십·합산 20명 제한을 적용한다.
- 지연 없는 실시간 관전
- 관전자는 다음을 모두 볼 수 있음:
  - 윷 결과
  - 결과 큐
  - 선택 가능한 말
  - 전체 채팅
  - 연결 상태
  - 남은 시간
  - 북 목적지
- 팀 채팅이 없으므로 비공개 팀 정보 없음
- 게임 중 관전자→플레이어 전환 및 새 플레이어 입장 불가
- 게임 전/후 관전자→플레이어는 방장 승인 필요
- 게임 전/후 플레이어→관전자는 방장 승인 없이 가능
- 플레이어+관전자 최대 20명

## 관리자 기능

운영자는 최소한 다음 기능을 가진다.

- 방 목록 조회
- 진행 중 경기 조회
- 방/경기 강제 종료
- 사용자 접속 차단
- 채팅 제재
- 서버 공지

세부 UI와 권한 모델은 기술 설계에서 확정한다. 모든 관리자 조치는 감사 로그에 기록한다.
