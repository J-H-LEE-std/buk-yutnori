# ADR-0022: 클라이언트 입력 자원 상한

- 상태: 채택
- 결정일: 2026-09-23

## 맥락

브라우저 셸은 서버 snapshot을 검증한 뒤 C/WASM staging ABI로 전달한다. 구조 검증은
엄격하지만 컬렉션과 문자열 크기에 독립적인 상한이 없으면 손상된 서버 응답이나 같은
origin의 비정상 스크립트가 WASM linear memory와 렌더링 시간을 과도하게 소비할 수 있다.
C 계층도 JavaScript 검증을 유일한 안전 경계로 신뢰하지 않아야 한다.

## 결정

- 말은 정본 최대 플레이어 8명과 플레이어당 말 4개에서 도출한 32개까지만 staging한다.
- 결과 큐의 표시 상한은 정본 턴 머신 및 스키마와 동일한 32개다. 이는 정상적인 연속 추가 던지기를
  수용하면서 16 KiB WebSocket 메시지 경계 안에서 클라이언트 메모리와 렌더링 비용을 제한한다.
- stack size는 전체 말 상한 32를 넘을 수 없다.
- 제한 초과는 해당 snapshot 전체를 실패시키며 이미 확정된 snapshot은 보존한다.
- JavaScript 셸은 C와 같은 말·결과 상한을 ABI 호출 전에 검사한다. 참가자는 방 정본의
  player+spectator 상한인 20명으로 제한한다. 나머지 중첩 컬렉션과 문자열에도 별도의
  방어 상한을 적용한다.
- 제한은 표시·자원 방어 계약이며 서버의 게임 판정이나 정본 상태를 변경하지 않는다.

## 결과

클라이언트는 유효하지 않게 큰 snapshot을 부분 적용하지 않는다. 실제 서버가 상한을
넘는 상태를 만들면 클라이언트는 추측하거나 잘라 표시하지 않고 재동기화 실패로
처리하므로, 서버와 클라이언트 제한 불일치는 관측 가능한 계약 오류가 된다.
