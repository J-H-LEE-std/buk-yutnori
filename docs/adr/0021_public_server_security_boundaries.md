# ADR-0021: 공개 서버 보안 경계

## 상태

- 채택
- Issue: #177
- Milestone: 6

## 배경

운영 서버는 Docker와 일반 리버스 프록시 뒤에 배포할 수 있으며 Cloudflare 같은 특정
엣지 서비스가 없더라도 온라인 추측과 연결 자원 고갈을 제한해야 한다. 반대로 전달된
클라이언트 IP 헤더를 무조건 신뢰하면 공격자가 제한 키를 위조할 수 있다.

## 결정

- 서버는 로그인 요청을 직접 peer 주소당 1분에 10회로 제한한다.
- 비밀번호 유무와 관계없이 방 입장 요청을 peer 주소당 5분에 10회로 제한한다. 방 ID를
  키에 넣지 않아 임의 방 경로로 제한기 key-space를 늘릴 수 없게 하고, 성공 여부를
  외부에서 추측하여 제한을 우회하지 못하도록 모든 시도를 센다.
- 제한 응답은 `429 Too Many Requests`, `Retry-After`, `Cache-Control: no-store`를
  반환하며 인증 서비스나 방 레지스트리를 호출하지 않는다.
- 기본 클라이언트 주소는 TCP peer다. `X-Forwarded-For`는 peer가 명시적으로 설정한
  신뢰 프록시 CIDR에 속할 때만 사용하고, 체인의 오른쪽에서 신뢰 프록시를 제거한 첫
  비신뢰 주소를 선택한다. 헤더가 잘못되면 peer 주소로 fail-closed한다. 모든 주소를
  신뢰하는 `/0` CIDR은 구성 오류로 거부한다. IPv6 클라이언트는 일반적인 주소 회전을
  통한 우회를 막기 위해 `/64` 프리픽스 단위로 제한한다. 여러 줄의
  `X-Forwarded-For`는 HTTP 목록 필드 규칙대로 하나의 체인으로 결합한 뒤 같은
  오른쪽-왼쪽 검증을 적용한다.
- WebSocket은 서버 전체 1,000개와 사용자당 5개로 제한한다. 인증과 프로필 확인 뒤,
  upgrade 전에 슬롯을 원자적으로 확보한다.
- 서버는 30초마다 WebSocket ping을 보내고 10초 안에 pong을 받지 못한 연결을 닫는다.
  종료 신호가 오면 활성 연결을 닫아 hijacked 연결이 shutdown을 가로막지 않게 한다.
- 브라우저 응답은 CSP, frame 차단, MIME sniff 차단, 최소 권한 정책을 서버에서 설정한다.
  시작 시 최종 `index.html`의 인라인 스크립트 SHA-256을 계산해 그 스크립트만 허용하며
  임의 `unsafe-inline` 스크립트는 허용하지 않는다. WASM 컴파일은 명시적으로 허용한다.
  HSTS는 TLS를 실제로 종료하는 계층에서 설정한다. 평문 개발 서버가 HSTS를 광고하지
  않는다.
- 제한은 프로세스 단위다. 여러 replica를 쓰는 배포는 공유 제한 저장소를 도입하기
  전까지 지원하지 않는다.
- 제한기 키 저장소는 만료 시각 순서의 65,536개 슬롯이다. 만료된 선두 슬롯은
  상각 O(1)로 제거하지만, 모든 슬롯이 유효한 채 포화되면 신규 키를 제한한다.
  유효한 버킷을 축출해 공격 횟수를 초기화하거나 전역 overflow 버킷을 공유하지 않는다.
- HTTP 요청 헤더는 64 KiB, 일반 요청 읽기·쓰기 시간은 15초로 제한한다.
- 배포 바이너리는 알려진 표준 라이브러리 취약점을 피하기 위해 Go 1.26.6 이상으로
  빌드하며 CI에서 `govulncheck`를 실행한다.

## 결과

프록시 없이 직접 노출해도 기본 방어가 동작하며, Docker 리버스 프록시는 신뢰 범위를
명시해야 실제 클라이언트별 제한을 사용할 수 있다. 프록시 설정 누락은 모든 요청을
프록시 하나로 제한하는 안전한 실패이며 제한 우회보다 가용성 저하를 택한다.
