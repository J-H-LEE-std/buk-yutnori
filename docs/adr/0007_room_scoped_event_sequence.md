# ADR-0007: 방 생명주기 단위 서버 이벤트 sequence

- 상태: 채택
- 결정일: 2026-08-16

## 맥락

WebSocket envelope에는 서버 이벤트 순서를 나타내는 `sequence`가 하나뿐이다. 기존
명세는 이를 경기별 단조 증가 값으로 설명했지만, 경기 전 `ROOM_UPDATED`, 대기실과
경기 중 채팅, 경기 종료 뒤 대기실 이벤트의 순서 범위는 정하지 않았다. 이 상태로는
클라이언트가 경기 밖 이벤트의 중복이나 공백을 일관되게 판단할 수 없다.

Milestone 2 한국어 채팅과 두 브라우저 동기화 전에 하나의 방에서 발생하는 모든
이벤트의 직렬화 경계를 확정해야 한다. 이 결정은 게임 규칙의 의미를 바꾸지 않으며,
네트워크 이벤트 순서와 생명주기 소유권만 정한다.

## 결정

- 모든 `server_event`의 `sequence`는 방 생명주기 단위로 증가한다.
- 방의 첫 이벤트는 `1`이며 현재 경계 `0`은 아직 확정된 이벤트가 없음을 뜻한다.
  현재 `game_snapshot`은 게임 시작 뒤 상태만 표현하므로 `sequence`가 항상 `1`
  이상이다. 향후 초기 방 스냅샷을 추가하면 이벤트 전 경계 `0`을 사용할 수 있다.
- 대기실, 채팅, 경기, 경기 종료 뒤 대기실 이벤트가 같은 sequence 범위를 공유한다.
- 경기 시작, 종료와 재대결은 sequence를 초기화하지 않는다. `match_id`는 이벤트가
  속한 경기를 식별하지만 별도 sequence namespace를 만들지 않는다.
- 방 application 생명주기 소유자가 sequence를 관리한다. WebSocket 전송 계층은
  sequence를 만들거나 수정하지 않는다.
- 동시 이벤트 확정은 방 안에서 직렬화하며 중복, 역전 또는 의도하지 않은 공백을
  만들지 않는다.
- 경기 상태 변경 이벤트는 ADR-0002에 따라 DB 저장 성공 뒤 sequence를 확정한다.
  채팅은 로그 저장 실패가 전달을 막지 않는 기존 정책에 따라 전달 확정 시 sequence를
  소비하고, 로그 저장은 비동기 최선 노력으로 재시도할 수 있다.
- 방 폐쇄 시 생명주기 소유자는 새 이벤트 유입을 중단하고 진행 중 확정을 끝낸 뒤
  메모리 sequence 경계를 제거한다. 폐쇄된 방 ID는 재사용하지 않는다.
- 클라이언트는 마지막 적용 sequence를 `room_id`별로 보관한다. 게임 스냅샷의
  `sequence`도 해당 방 전체 이벤트의 원자적 경계다.

## 대안

- 경기 sequence와 방·채팅 sequence를 별도로 두면 한 envelope 필드의 namespace를
  추가로 표현해야 하고, 경기 전후 이벤트의 상대 순서가 모호해진다.
- 서버 전체 전역 sequence는 서로 무관한 방의 공백을 클라이언트에 노출하고 방별
  재접속에 불필요한 결합을 만든다.
- 경기나 대기실 전환 때 sequence를 초기화하면 늦게 도착한 이전 단계 이벤트와 새
  이벤트를 값만으로 구분할 수 없다.

## 결과

- 같은 방의 상태·채팅·경기 이벤트는 하나의 순서로 재생하고 공백을 감지할 수 있다.
- 재대결 뒤에도 이전 이벤트와 새 이벤트의 순서가 충돌하지 않는다.
- 현재 `RoomEventSequences`는 동시성 안전한 메모리 경계만 제공한다. 이벤트 저장,
  방 actor, 방송과 재접속 replay는 후속 application 구현이 소유한다.
- sequence 공백을 발견했을 때 사용할 재동기화 명령과 오류 코드는 별도 미결정
  항목으로 남는다.
