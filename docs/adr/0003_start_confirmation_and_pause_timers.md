# ADR-0003: 시작 확인과 일시 정지 타이머

- 상태: 채택
- 결정일: 2026-07-23

## 시작 확인

- 서버가 `GAME_STARTING`을 확정할 때 서버 기준 10초 마감 시각을 정한다.
- 마감까지 응답하지 않은 플레이어를 퇴장시킨다.
- 미응답자가 한 명이라도 있으면 시작을 취소하고 남은 전원의 준비 상태를 해제한다.
- 퇴장, 취소와 준비 해제는 하나의 방 상태 전이다.
- 늦은 응답은 취소된 시작을 되살리지 않는다.

## 일시 정지

- 방장은 경기당 한 번, 1분 단위로 1~30분을 요청할 수 있다.
- 정지 시 활성 타이머 종류와 남은 밀리초를 보존한다.
- 재개 시 같은 타이머를 보존 값부터 이어간다.
- 정지 중 게임 타이머와 CPU 행동은 멈추지만 양 팀 전원 이탈 30초 감시는 계속한다.
- 방장 연결 해제, 조기 재개 또는 지정 시간 만료는 기존 재개 규칙을 따른다.
- DB 저장 장애 자동 정지는 사용자 일시 정지 사용량을 소비하지 않는다.

## 구현 제약

타이머는 클라이언트 카운트다운이 아니라 서버의 단조 시계 기반 마감 시각과 보존된
남은 시간으로 계산한다. 벽시계 변경이 경기 시간을 늘리거나 줄이지 않게 한다.

- 실행 중인 서버에서 만든 절대 마감 시각은 `time.Time`의 단조 시계 정보를 유지한 채
  현재 시각과의 차이로 남은 시간을 계산한다. 클라이언트 표시용으로 직렬화한 벽시계
  문자열을 다시 읽어 authoritative timer를 만들지 않는다.
- 이미 지난 마감 시각의 남은 시간은 0으로 제한하여 즉시 만료 대상이 되게 한다.
- timer goroutine은 방 상태를 직접 바꾸지 않고 만료 operation을 같은 방 actor에
  제출한다.
- deadline 취소는 actor admission 전의 timer 대기와 제출만 중단한다. actor가 이미
  수락한 operation은 취소하거나 롤백하지 않고 끝까지 완료한다.
- deadline 완료를 기다리는 caller context와 deadline 자체의 취소 소유권은 분리한다.
  단순히 `Wait`를 포기해도 예약된 operation은 취소되지 않는다.
- 방 actor가 deadline admission 전에 닫히면 남은 timer를 즉시 정리하고 폐쇄 결과를
  deadline owner에게 전달한다.
